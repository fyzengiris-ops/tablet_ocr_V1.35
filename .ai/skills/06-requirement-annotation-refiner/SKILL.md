# 需求注释表达清洗 Skill

## 目标

清洗当前项目需求注册表里的用户可见说明，让业务逻辑更短、更清楚、更可验收。

本 Skill 只处理表达质量，不重新做业务决策。

执行前必须先读：

```txt
.ai/skills/shared/project-context.md
.ai/skills/shared/logic-writing-spec.md
src/requirements/schema.ts
src/requirements/index.ts
```

若指定页面，还要读：

```txt
src/requirements/<页面或流程>.registry.ts
```

## 前置条件

1. `src/requirements` 需求注册表已生成。
2. 页面角标、悬浮面板或右侧 PRD 面板已经按现有 `display` / `operation` 读取 registry。
3. 用户明确要求清洗、压缩、去重、调整表达或处理空兜底。

若用户想新增业务规则、改变口径或补充未确认逻辑，应回到 Skill1 或 Skill2，不要在本 Skill 中擅自新增。

## 可以做

- 精简啰嗦表达。
- 去除 `display` 和 `operation` 之间的重复描述。
- 把展示逻辑放回 `display`，把操作、流转、权限、异常放回 `operation`。
- 删除空兜底说明，例如“无额外权限限制”“无异常场景”“本对象仅展示”。
- 保持产品语言，减少技术实现词。
- 在不改变含义的前提下统一同一页面内的表达风格。
- 检查标题是否在正文完成后按实际业务维度生成；可在不改变正文含义的前提下，把固定、宽泛或与正文不匹配的标题改为简短准确的标题。

## 不可以做

- 不改变 `id`、`anchorId`、`anchorStatus`、`activate`、`sourceType`。
- 不重排已有编号。
- 不合并或拆分需求项，除非用户明确要求。
- 不改页面组件、角标位置、右侧 PRD 面板逻辑。
- 不新增未确认业务规则。
- 不迁移到 `logicSections`。

## 清洗规则

### display 只写展示逻辑

保留：

- 页面展示什么。
- 什么状态或条件下展示。
- 文案、数量、列表、按钮、禁用态、空状态如何呈现。

移出：

- 点击后如何流转。
- 保存到哪里。
- 接口失败怎么处理。
- 权限限制。

### operation 只写操作逻辑

保留：

- 用户点击、上传、切换、删除、重试、加入试卷后发生什么。
- 操作前置条件和拦截规则。
- 结果如何保存、传递或影响下一步。
- 权限、数据流转、异常处理。

移出：

- 纯展示内容。
- 与 `display` 重复的状态描述。

### 空兜底过滤

删除或不展示：

- 无额外权限限制
- 无额外数据流转
- 无异常场景
- 本对象无操作入口
- 本对象仅展示
- 暂无
- 无
- 空字符串
- 空数组

### 表达标准

- 每条一句，能直接验收。
- 不写“大概”“尽量”“优化体验”等空话。
- 不写接口名、组件状态、DOM、缓存键等实现细节。
- 保留用户已确认的业务口径，不改变含义。
- 发现原规则本身不清楚时，停止并列出需回到 Skill1 确认的问题。
- “显示说明”“操作说明”“数据流转”“异常”“统计口径”“数据规则”等均为标题示例，不是固定栏目。标题必须与本组正文实际内容匹配，且只为非空业务逻辑生成。

## 执行流程

1. 明确用户指定的清洗范围。
2. 读取 `project-context.md`、`logic-writing-spec.md`、`schema.ts` 和目标 registry。
3. 逐条检查 `display` / `operation` 是否重复、错位、啰嗦或有空兜底，并检查标题是否固定套用、过于宽泛或与正文不匹配。
4. 只修改目标 registry 中的说明文字。
5. 运行 `pnpm ts-check`。
6. 输出改动摘要和验证结果。

## 完成摘要

```md
一、清洗结果
- 已清洗注册表：src/requirements/<页面或流程>.registry.ts

二、主要调整
- 去除了 display / operation 中的重复描述
- 删除了空兜底说明
- 调整了展示逻辑与操作逻辑的归属

三、未处理范围
- <如有>

四、验证结果
- pnpm ts-check：通过/失败/未运行（说明原因）
```
