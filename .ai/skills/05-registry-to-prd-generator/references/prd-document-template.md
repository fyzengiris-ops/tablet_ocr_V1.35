# 页面级 PRD 文档模板

生成页面级 Markdown PRD 时，使用下面结构。

当前保守方案下，业务逻辑章节来自需求注册表的 `display` + `operation`，不要要求 `logicSections`。

## 模板

```md
# <页面名称> PRD

## 1. 页面范围

### 1.1 当前页面
- 页面名称：
- 所属模块：
- 页面路由/视图：
- 相关代码文件：

### 1.2 上级页面/上游入口
- 上级页面：
- 入口位置：
- 进入方式：
- 传入数据：
- 依赖状态：

### 1.3 下级页面/下游流程
- 下级页面/下游流程：
- 触发方式：
- 传出数据：
- 后续状态：
- 返回逻辑：

### 1.4 范围边界摘要
- 本文档覆盖：
- 本文档不覆盖：

## 2. 功能概述

<简述页面解决什么问题、服务什么场景、当前文档覆盖哪些能力。>

## 3. 业务逻辑说明

### <需求编号> <需求标题>

来源：<代码事实 / 确认决策 / 代码事实 + 确认决策>

#### 显示说明

#### 操作说明
1. <operation.description 条目>

#### 权限规则

#### 数据流转
1. <operation.dataFlow 条目，如有>

#### 异常情况处理
1. <operation.exceptions 条目，如有>

#### 验收标准
1. ...

## 4. 范围边界

### 4.1 本文档覆盖

- ...

### 4.2 本文档不覆盖

- ...

## 5. 验收标准

### <需求编号>

1. ...

## 6. 来源追溯

- 需求注册表：
- 来源决策文件：
- 相关代码文件：
```

## 业务逻辑填写规则

- 读取 `requirement.display` 和 `requirement.operation`。
- `display.description` 输出到“显示说明”。
- `operation.description` 输出到“操作说明”。
- `operation.permission`、`operation.dataFlow`、`operation.exceptions` 只在有有效内容时输出。
- 有内容才写章节；不要硬补空栏目。
- 不要输出未迁移的 `logicSections` 字段。

## 上游/下游填写规则

### 当前页面

读取：`pageName`、`module`、`route`、`relatedFiles`。

### 上级页面/上游入口

- 当前视图从哪个路由、按钮、弹窗或步骤进入。
- 上游传入哪些文件、识别方式、框选结果或识别结果。
- 依赖哪些上下文状态。

### 下级页面/下游流程

优先从 `display` / `operation`、`activate` 与代码事件判断：

- 点击哪个入口触发下游。
- 是否打开弹窗、切换步骤、提交识别或加入试卷。
- 是否传出题目、答案、解析、题型或其他数据。

无明确下游时写“未在当前代码或注册表中确认明确下游流程”。

## 过滤规则

默认过滤空兜底：

- 无额外权限限制
- 无额外数据流转
- 无异常场景
- 本对象无操作入口
- 本对象仅展示
- 空字符串
- 空数组

## sourceType 中文映射

- `code`：代码事实
- `decision`：确认决策
- `code+decision`：代码事实 + 确认决策
