# 页面对象清单 Skill（Skill0）

## 目标

在 Skill1 深度审核之前，先把“可能需要写业务逻辑的页面对象”扫成一张清单，让用户对着页面核对：

- 有没有漏掉文案、按钮、状态、区域。
- 哪些必须进 Skill1 审核。
- 哪些可以跳过（无业务含义或不在本期范围）。

**本 Skill 只锁“审什么”，不定“怎么定”。**

明确不做：

- 不出 `1A2C3D` 决策题。
- 不写完整业务逻辑 / PRD / 需求注册表。
- 不把每个可见元素都当成必审对象。
- 不直接改页面代码。

执行前必须先读：

```txt
.ai/skills/shared/project-context.md
```

## 在整体流程中的位置

```txt
定范围/前提 -> Skill0 出清单并经用户确认 -> Skill1 只审“必审” -> Skill2 …
```

- Skill0 必须在 Skill1 之前完成并得到用户确认。
- Skill1 不得对清单外对象擅自开审；用户补漏后，先回 Skill0 更新清单，再进 Skill1。
- Skill2 及之后仍以 Skill1 决策记录为准；本 Skill 不替代决策。

## 必须遵循的流程

1. 先确认本次页面/流程范围，例如 `/tablet-ai-entry`、上传资料弹窗、选择识别内容步骤、校对识别结果步骤。
2. 再确认前提信息，例如目标用户、本期范围、明确不做的能力、重点关注方向。若用户无额外前提，可回复“无额外前提”。
3. 用一句话复述范围与前提后，再读代码/页面结构。
4. 读取当前 Next.js 项目相关文件，优先：
   - `src/app/tablet-ai-entry/tablet-ai-entry-preview.tsx`
   - `src/components/UploadQuestionDialog.tsx`
   - 已有 `src/requirements/*.registry.ts`
   - 相关 `src/components/prd/*.tsx`
5. 同时查找 PC 端对应能力，优先用页面文案、组件名、接口路径、需求编号搜索；找不到时标记为“未确认 PC 对应项”，不要硬套。
6. 覆盖弹窗、步骤条、Tab、上传列表、框选区、识别结果、空状态、失败态、禁用态等隐藏或切换内容。
7. 按“候选对象扫描清单”扫出对象，并给出建议处置：`必审` / `可跳过` / `待你定`。
8. 按“首次输出格式”交给用户核对；请用户补漏、改处置、确认清单。
9. 用户确认后，写入清单文件，并明确告知：下一步可执行 Skill1，且 Skill1 只审“必审”项。

## 候选对象扫描清单

| 类型 | 平板端 OCR 示例 |
| --- | --- |
| 标题/范围文案 | 识别作业资料、上传资料、选择识别方式、校对识别结果 |
| 步骤条 | 上传资料、选择识别方式、选择识别内容、校对识别结果 |
| Tab / 维度切换 | 本地上传、我的资源库、智能切题、手动画框 |
| 表单字段 | 学段学科、资料类型、题型、答案、解析 |
| 列表/卡片区域 | 已上传文件列表、题目列表、识别结果列表 |
| 操作按钮 | 上传资料、下一步、上一步、重新识别、加入试卷、关闭 |
| 框选对象 | 题干框、答案框、手动补框、删除框 |
| 状态标识 | 上传中、识别中、已识别、失败、空状态、禁用态 |
| 异常入口 | 网络错误、接口失败、无识别结果、文件格式不支持 |
| 数据流转对象 | 文件、切题框、识别文本、题目答案匹配结果 |

扫描原则：

- 以用户能感知的业务对象为单位，不拆 CSS 装饰和纯图标细节。
- 同一决策单元可合并为一行；若文案、规则或验收点不同，应分行。
- 隐藏态也要扫：弹窗内后续步骤、失败提示、空状态、禁用按钮。
- 明确“不在本期范围”的仍可列入，但建议处置标为 `可跳过` 并说明原因。

## 建议处置口径

| 处置 | 含义 | 何时用 |
| --- | --- | --- |
| 必审 | 需要 Skill1 出决策题 / 写清业务口径 | 影响展示规则、操作结果、数据流转、异常、状态流转 |
| 可跳过 | 本期不进 Skill1 | 纯装饰；或用户已声明不在范围；或仅布局无业务分歧 |
| 待你定 | 模型拿不准 | 可能有业务含义，但不确定是否值得本期审核 |

默认偏保守：拿不准标 `待你定`，不要擅自标 `可跳过` 后在 Skill1 消失。

## 首次输出格式

必须用中文，严格使用以下结构：

```md
一、页面名称
<页面名称>（<路由或主要文件>）

二、前提与范围
- 前提：<用户前提或“无额外前提”>
- 本期明确不审/不做：<如有>

三、对象清单（请对着页面核对）

| 序号 | 对象 | 类型 | 页面位置 | PC 对应对象/能力 | 建议处置 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | <对象名> | <标题/Tab/文案/状态/按钮/区域/筛选…> | <何处可见> | <PC 对应入口/组件/未确认> | 必审 / 可跳过 / 待你定 | <一句理由；可跳过必写原因> |

四、请你确认
请对照页面看是否有遗漏，并回复例如：
- `确认清单`
- `确认清单；补充：xxx、yyy 为必审`
- `确认清单；3改为可跳过；5改为必审`
- `还有遗漏：<对象A>、<对象B>`
```

## 清单文件

用户确认后，创建或更新：

```txt
产品文档/prd-workflow/inventories/<页面或流程>.inventory.md
```

文件结构：

```md
# <页面名称> 对象清单

## 页面范围
- 页面/流程：<名称>
- 路由：<例如 /tablet-ai-entry>
- 相关代码文件：
  - <file>
- PC 对照文件：
  - <file 或 未确认>
- 前提：<...>
- 本期不审/不做：<...>

## 清单状态
- 状态：已确认
- 确认说明：<用户确认原话摘要>

## 必审对象
1. <对象> - <类型> - <页面位置> - PC 对应：<对象/能力/未确认> - <备注>

## 可跳过对象
1. <对象> - <原因>

## 供 Skill1 使用的约束
- 只对“必审对象”输出待确认问题。
- Skill1 审核时必须同时对照清单中的 PC 对应对象/能力；PC 已明确且 Pad 无差异的业务口径默认沿用。
- 发现清单外仍有关键业务对象时：先回到 Skill0 补清单并经用户确认，再继续 Skill1。
- 不要把“可跳过对象”重新展开成决策题，除非用户主动要求加入。
```

在用户说出明确确认之前，不要写入清单文件，也不要开始 Skill1。
